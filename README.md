## 一、这个系统在监测什么

| 曲线 | 含义 | 对标 |
|---|---|---|
| `pct_above_5` | 站上 5 日均线的股票占比 | `S5FD`，超短线情绪 |
| `pct_above_20` | 站上 20 日均线占比 | `S5TW`，1~4 周动能 |
| `pct_above_50` | 站上 50 日均线占比 | `S5FI`，中期趋势持续性 |
| `pct_above_200` | 站上 200 日均线占比 | `S5TH`，长期循环强度 |
| 沪深 300 / 上证综指 / 创业板指 | **独立图 2**：与 MA200 占比一起做归一化分位对比（滚动 250 日默认 / 1300 日可切换），背景 Spread 显示背离 | 与宽度共用时间轴、共同缩放 |
| 涨跌家数 / McClellan | 每日上涨、下跌家数与 EMA19−EMA39 | 广度动量 |

宽度是**等权**的，一只股票一票，不看市值。指数涨但宽度掉头，通常说明是少数权重在撑，属于典型脆弱结构——这正是这套指标的价值。

## 二、指标怎么算（S5TH 口径）

### 2.1 定义

`pct_above_N(t) = 当日「后复权收盘价 > 自身 N 日均线」的股票数 / 当日有效样本数`

### 2.2 复权：为什么必须用 `hfq`

`.day` / 东财不复权价格在除权日会出现人为跳空，直接算均线会得到假跌破。本地通达信版曾用 `gbbq` 自己算前复权；云端版直接取 `stock_zh_a_hist(adjust="hfq")` 后复权序列，价格天然连续。`close > MA_N(close)` 在整体等比例缩放下不变，所以前复权与后复权等价，且后复权历史值不会因未来分红被改写，更适合做 5 年时间序列。

**实测锚点**：2026-09-21，不复权 MA200 占比 24.61%，复权后 27.57%，差约 3 个百分点。

### 2.3 分母与样本（最容易算错的地方）

- 股票池：沪深京 A 股正股（600/601/603/605/688/689、000/001/002/003/300/301、43/83/87/92 开头），排除指数、基金、债券、B 股；ST 未单独剔除
- 剔除上市不足 `MIN_BARS`（51）根日线的股票；**停牌日不计入当日分母**
- **每档均线独立分母**：不足 200 根日线者不进 MA200 分母，MA200 还没算出来的股票不能算成「未站上」，否则 5 年曲线左端会被系统性压低
- MA 按个股自己的交易日序列滚动（跳过停牌），与行情软件口径一致

### 2.4 5 年历史是「回算」，不是「存档」

`LOOKBACK_DAYS=2400` 天（约 6.5 年），每次运行都把全市场历史拉回来重算最近 **1300 个交易日**（约 5 年）。所以 **CSV 不需要一天天累积**，也不会随时间漂移。

代价是**幸存者偏差**：5 年前的宽度是用「今天还在池子里的股票」回算的，当时未上市 / 现已退市的股票不在其中，越往前分母越小。看板底部与第十一章都写明了这一点，严禁把早期数值表述成「当时的真实全市场宽度」。

### 2.5 三大指数为什么单独开图

指数**不再和宽度曲线画在同一张图**：主图只留 MA50 / MA200，指数与 MA200 占比一起放到正下方的独立图 2，三图 `echarts.connect` 共同缩放。这样短期噪声不与长期宽度混淆，背离又能上下对照着看。

归一化在 Python 端算好、烤进页面，**按滚动窗口 min-max 映射到 0-100（250 日默认，图 2 可切 1300 日 / 约 5 年），只用当日及之前数据、不随图表缩放重算**（旧版按当前显示窗口归一化会口径漂移，已废弃）。`Spread = MA200 占比分位 − 基准指数分位`，正红负绿铺在曲线背后。完整公式、配色、阈值与两个百分位的区别见 **第五章 / 5.1**。指数序列用 `connectNulls` 补齐空洞。

### 3.0 数据源总表（先看这张）

### 3.1 `wj624/a-stock-api` 评估结论：**不是更好，不能当主源**

| 本项目需要 | 该数据源 | 判定 |
|---|---|---|
| 全市场逐股历史日线 | README 明确 `/api/spot` 未提供（push2 分页 60 页 > 免费 Worker 50 子请求） | ❌ |
| 复权收盘价 | `/api/kline` 无 `adjust`；`/api/futures-kline` 明确未复权 | ❌ |
| 站上 N 日均线的历史序列 | `/api/market-breadth` 仅当日快照，`history_supported` 恒 false、忽略 `date` | ❌ |
| 当日涨跌 / 涨停 / 连板 | 一次请求，云出口实测可达 | ✅ |
| 交易日历、指数日 K | `/api/trade-calendar`、`/api/kline` 可用 | ✅ |

本项目只把它用在两处：**① 用 `date` 做幂等判断**（兜底 cron 命中当天就不重复拉 5900 只）；**② 结果页「当日快照校验」卡片**。它失败时主流程照常跑完。

### 3.2 它暴露的真问题：push2 的 WAF → 三级代码池链路

该 README 明确写「东财 `push2.eastmoney.com` 对 Cloudflare / 云出口 IP 有 WAF 拦截（502）」，而 `stock_zh_a_spot_em` 正是 push2。代码清单因此做成三级链路，**任何一级成功都会把结果写回随仓库提交的 `codes.txt`**：

| 级别 | 来源 | 实测 | 特点 |
|---|---|---|---|
| ① 主源 | `stock_zh_a_spot_em()` | 5927 行 / 约 76 秒 | 完整快照，含新股与退市整理股 |
| ② 备用源 | `stock_info_a_code_name()` | 5579 行 / 约 8.5 秒 | 走**不同端点**，纯在市清单；两源差的 345 只实测全是最新价为 NaN 的退市 / ST 整理 / 长期停牌股，因此备用源反而更干净 |
| ③ 兜底 | `codes.txt` | 本地文件 | 只在 ①② 同时失败时启用，**不刷新日期**，让陈旧度可见 |

`codes.txt` 第一行是机器可读的日期标记，普通代码行不受影响（`read_codes_file` 只收数字开头的行）：

```
# updated: 2026-11-07 | source: online | count: 5923
000001
000002
...
```

逐股历史走 `push2his`，不受这条 WAF 限制；主源挂掉不会拖垮整个计算。

### 3.3 单位、颜色与口径

- 价格单位：元（后复权），仅用于相对比较，**不是可成交价**
- 宽度单位：百分比 0-100；McClellan：家数差（无量纲）
- **红涨绿跌**：上涨 `#d64545`、下跌 `#1f9d6b`（A 股习惯，严禁反色）
- 图 2 分位为滚动 min-max 归一化 0-100（250 日默认 / 1300 日可切换），Spread 取值 −100 ~ +100；「显示原始走势」模式下指数为窗口首日 = 100 的右轴基准值。两者都是形状对比，不代表收益率

### 3.4 明确剔除项

指数、基金、债券、B 股、北交所指数、**上市不足 `MIN_BARS`（51）根日线者**、停牌日、数据停更 / 退市股。**ST 未剔除**（与 TradingView 成分股口径不同，是有意选择）。

> 旧版在这里写的是「上市不足 200 交易日者剔除」，对应代码里的 `len(df) < 205` 双重硬门槛——那会把新股**整只丢掉**，连 MA5 宽度都进不了，而 `ready` 矩阵本来已支持每档均线独立分母。现改为 51 根（MA50 需要 50 根 + 1）：新股约 2.5 个月后进入 MA5/20/50 宽度，满 200 根才进入 MA200 宽度。**若要恢复旧口径，把 `breadth.py` 的 `MIN_BARS` 改回 205 即可，只有这一个常量。**

### 3.5 新上市 / 合规入选的股票会自动更新吗？

| 事件 | 自动？ | 机制 |
|---|---|---|
| **新股上市** | ✅ 自动 | 每次运行第 1 步重新拉当日全市场清单并写回 `codes.txt`，新股代码当天进入取数队列 |
| **退市 / 摘牌** | ✅ 自动 | 代码从在线清单消失；备用源本身就不含退市股 |
| **ST 戴帽 / 摘帽** | 不适用 | 证券代码不变，且本项目有意不剔除 ST，池子无需变化 |
| **沪深300 等指数成分股调整** | 不适用 | 宽度股票池是**代码前缀白名单**（全市场 A 股正股），不是指数成分股；三大指数只用于叠加对比曲线，成分调整不影响宽度分母 |
| **上市未满 200 日的新股** | 分档自动 | 满 51 根日线进 MA5/20/50 分母，满 200 根才进 MA200 分母，由 `ready` 矩阵逐档把关 |

也就是说：**股票池本身不需要人工维护**。唯二会让它停滞的情况，系统都做了显式处理而不是静默：

1. **主源 + 备用源同时长期不可用** → 走 `codes.txt` 兜底，页面出现橙色告警条「代码池兜底 · 已 N 天未刷新」，日志同步打印；`codes.txt` 日期不会更新。
2. **幂等跳过把刷新也跳掉** → 主程序在跳过前先读 `codes.txt` 头部日期，若超过 `POOL_MAX_AGE_DAYS = 7` 天（覆盖春节 / 国庆长假）就**禁止跳过、强制重拉清单**。正常交易日每天刷新，幂等省时仍然生效。

结果页卡片下方常驻一行绿色状态条，显示「股票池来源 / 刷新日期 / 只数」；降级时变橙色。**看到橙色条才需要人工介入**，绿色即代表新股与退市股都在自动同步。

### 5.1 归一化与开口差（照搬 `wj624/etf-lsi` 口径）

```
归一化分位 pct[i] = (x[i] − min(x[i−N+1..i])) ÷ (max(x[i−N+1..i]) − min(x[i−N+1..i])) × 100
滚动窗口 N = 250（默认，约 1 年） 或 1300（图 2 可切换，约 5 年全序列）
每个点只取「自己及之前 N−1 个交易日」，不使用未来极值；不是整段固定 min-max
Spread[i] = MA200 占比分位[i] − 基准指数分位[i]        取值 −100 ~ +100
```

- **为什么都必须是滚动窗口**：整段**固定** min-max 会用未来极值、把近端压成水平线，±25 劈叉阈值也失效。两种周期都只用「当日及之前」的数据，且**不随图表缩放窗口漂移**（旧版按当前显示窗口归一化会漂移，已废弃）。注意 1300 日窗口在**最后一个点**上数值等价于整段 min-max，但历史点仍是累计口径，不含未来数据。
- **两种周期怎么选（v3.5 新增）**：`250 日滚动`（默认）看近一年相对位置，中短期背离灵敏；`5 年周期`（图 2 标题下方按钮切换）看长期历史位置，但近端波动会被压平。实测 2026-11-06：MA200 占比分位 **4.75 → 6.32**，Spread(vs 沪深300) **−1.65 → −36.45**（5 年视角下变成大劈叉），两套分位有 761/1300 个点不同。两套都由 Python 端 `rolling_minmax_pct()` 算好烤进 payload（`p200Pct`/`indexPct` 与 `p200Pct5y`/`indexPct5y`），**前端只切换取哪一套，绝不在浏览器里重算**。切换会同步更新 Spread 背景、曲线、说明文字与悬停窗口标注，并保留图例勾选状态。
- **红绿背景**：`Spread > 0` 红 `#E8453C`（宽度领先）、`Spread < 0` 绿 `#1FB37A`（指数领先），A 股红涨绿跌；20% 透明柱状铺在底层，前景是归一化曲线，右轴另有细 Spread 线。
- **|Spread| ≥ 25 为大劈叉**，右轴固定 −100 ~ +100 并画 ±25 / 0 三条虚线；悬停显示当日 MA200 占比、各指数原始值与分位、Spread 数值与状态。
- **背离基准可切换**：默认沪深300（与参考页面一致），下拉可切上证综指 / 创业板指，Spread 与说明文字同步更换。
- 归一化是**形状对比，不是收益率**：指数用收盘价、MA200 占比用百分比，各自映射到 0-100 后同竖轴可比。

### 5.2 两个「百分位」不要混淆

| 指标 | 位置 | 定义 |
|---|---|---|
| 归一化分位 | 图 2 曲线与 Spread | 滚动 min-max（250 日默认 / 1300 日可切换），0-100，相对位置 |
| **5 年百分位比值** | 页面头部 | 当前 MA200 占比在近 1300 个交易日中的 **percentile rank** = 低于/等于当前值的交易日占比 |

|---|---|---|
| 图 1 宽度曲线（中长期） | 站上 200 日线（S5TH 同类）、MA200 占比长周期 EMA | **站上 50 日线** |
| 图 2 归一化背离对比 | MA200 占比分位、沪深300 分位、Spread 背景 | **上证综指 分位、创业板指 分位** |

实现约定（改前端前必读）：

- 默认靠 `legend.selected` 初始化：图 1 写死 `{'站上 50 日线':false}`；图 2 由 `idxLegendSelected()` 生成，按 `IDX_KEYS` 给 `hs300` 默认 `true`、其余 `false`。
- **不要挂 `legendselectchanged` 事件来缓存用户偏好**。`dispatchAction({type:'legendSelect'})` 不触发该事件，用事件缓存会出现「手动勾选丢了」的假象；正确做法是 `refreshIdx()` 时由 `idxChart.getOption().legend[0].selected` 读取图表实例的**真实**状态，`pick()` 在无记录时兜底默认值。
- 图 2 切换「归一化分位 / 原始走势」时 series 名称从 `<名称> 分位` 变成 `<名称>（基准 100）`，图例项会重建。所以 `idxLegendSelected()` 必须按**指数 key** 在两套命名之间映射，否则每次切换都会把用户勾选重置回默认；MA200 占比的两种命名同理。
- 验收口径：headless Chrome 加载 `docs/index.html`，确认 3 个 `<canvas>`，并分别检查「零操作来回切换视图」与「手动勾选上证后切换视图」两种场景下 `getOption().legend[0].selected` 符合预期。

### 5.5 标题旁的数据日期与「最新」判断

用户要「一眼看出当前是不是最新数据」，所以把日期从底部说明提到大标题右侧：

| 显示项 | 来源 | 说明 |
|---|---|---|
| 数据日期 `2026-11-06` + 星期 | `__LATEST__` = CSV 最后一个交易日 | **最可靠的判据**，前端 `markFreshness()` 也从 `DATA.dates` 末位取同一个值 |
| 页面更新时间 | `__GEN__` = `generated_at` | **统一北京时间**（`BJ_TZ`），不是 UTC，也不是「数据交易日」 |
| 「最新」绿色 / 「距数据日 N 天」橙色 | 纯前端 `markFreshness()` | 辅助提示，不作断言 |

判断口径（写在 `freshTag.title` 里，鼠标悬停可见）：北京时间 **18:30 之前**期待「上一工作日」的数据，之后期待「当日」的数据；周六日跳过；`latest >= 应有交易日`（`YYYY-MM-DD` 字典序即时间序）即显示「最新」，否则显示自然日差。18:30 来自 18:00 兜底 cron + 30 分钟余量。

**边界必须讲清楚**：法定节假日 / 临时休市纯前端无法识别，长假期间会误报橙色「距数据日 N 天」，所以文案只陈述天数、不说「故障 / 滞后」，最终一律以徽章上的**数据日期**为准。别为了消除这个误报去引入交易日历接口——那会破坏「无外部依赖的静态页」这条设计底线。

## 九、防 Bug 铁律（改动代码前必读）

> **以下 17 条均来自真实踩坑，严禁回退。**

1. **必须用后复权 `adjust="hfq"`**。严禁用不复权收盘价直接算 MA：除权日会假跌破，实测 MA200 占比差约 3 个百分点（24.61% vs 27.57%）。
2. **`codes.txt` 兜底不能删，且每个在线源都有写回下限**（主源 ≥3000、备用源 ≥5000 只）。push2 对云出口有 WAF 502；把异常小的快照写进兜底文件，等于把一次限流放大成长期数据空洞。**头部 `# updated | source | count` 注释行不能删**，`read_codes_meta()` 靠它判断陈旧、`read_codes_file()` 靠「首字符是数字」跳过它。
3. **「200 + 空数组」不等于「今天没数据」**。有效样本 < `MIN_VALID` 或取数成功 < 200 只时，必须非 0 退出且**不覆盖** `docs/`；严禁用前一日数据顶替缺失日。
4. **停牌日不计入当日分母，每档均线独立分母**。把 MA200 无值的股票算成「未站上」，会让 5 年曲线左端系统性偏低且不会报错。
5. **交易日历用全市场个股日期并集（阈值 30%）**，严禁只依赖指数文件。本地版用上证指数日历时曾误剔 920 只股票。
6. **红涨绿跌**：上涨 `#d64545`、下跌 `#1f9d6b`。严禁反色。
7. **依赖锁死 `akshare==1.20.21 / pandas<3 / numpy<3`**。pandas 3.x 移除 `resample('M')` 等 API，会打断 akshare 内部逻辑；升级前必须本地全量验证。
8. **境外 runner 四件套不能删**：`socket.setdefaulttimeout(12)`、并发 10、重试 2、`timeout-minutes: 90`。akshare 内部 `requests` 未设超时，境外遇连接问题会挂死；实测 v2 全量重算 19.9 分钟成功、幂等跳过 0.4 分钟，v3 改 5 年窗口后取数更重，故上限留到 90 分钟。
9. **5 年历史是「当前股票池回算」**，有幸存者偏差。严禁在页面 / 文档里表述为「当时的真实全市场宽度」。
10. **HTML 用唯一占位符 `__XXX__` 整段替换，不用 f-string 拼整页 JS**。一处括号转义错整页图表全废；生成后必须抽出 `<script>` 跑 `node --check`。
11. **仓库内绝不写任何 PAT / Token**，CI 用 `GITHUB_TOKEN`；提交前 `grep -R "ghp_"` 扫一遍。
12. **绝不 force push、不重写 main 历史**。500 MB 清理只裁剪 `docs/` 数据文件，正常 commit。
13. **股票池每次运行必须重新拉当日清单**，禁止把 `codes.txt` 当静态成分股表直接复用。新股上市、退市摘牌全靠这一步同步；`codes.txt` 只是三级链路的最后兜底。降级到备用源 / 兜底时必须在结果页打橙色告警条，不许静默。
14. **幂等跳过前必须先检查代码池陈旧度**。只看辅助源 `date` 会让一次长期兜底把新上市股票永久挡在门外（`get_codes()` 根本没被调用）；`POOL_MAX_AGE_DAYS = 7` 与 `read_codes_meta()` 不能删。**`MIN_BARS` 只改一个常量就能回退口径**，不要在 `fetch_one()` / `compute()` 里各写死一个数字。
15. **归一化分位默认是滚动 `PCT_WINDOW=250` 日窗口，图 2 可切换滚动 `PCT_WINDOW_5Y=1300` 日窗口，但两者都必须只用「当日及之前」的数据**。严禁整段**固定** min-max（会用未来极值、把近端压平、±25 阈值失效），严禁按当前显示窗口归一化（缩放时口径漂移），严禁在前端重算（两套分位必须由 Python 端 `rolling_minmax_pct()` 一次算好烤进 payload，前端只切换取哪一套）。5 年周期近端会被压平是已知限制，页面必须标注且不得设为默认。Spread 正红 `#E8453C` / 负绿 `#1FB37A` 是 A 股红涨绿跌，不许反色。切换图 2 series 必须用 `replaceMerge:['series']`，普通 `setOption` 会残留旧曲线。
16. **图例显隐状态只能从图表实例读，不许用 `legendselectchanged` 事件缓存**。`dispatchAction` 不触发该事件，`refreshIdx()` 若把事件缓存的 `selected` 写回去会覆盖用户勾选。三条默认关闭的曲线（图 1 `站上 50 日线`、图 2 `上证综指 分位` / `创业板指 分位`）必须仍可手动勾选；图 2 切换视图时 series 改名，要按指数 key 映射两套命名，不能让默认关闭项被重置为显示。
17. **页面所有时间统一 `BJ_TZ`（UTC+8），不许用裸 `datetime.now()`**。GitHub Actions runner 是 UTC、本地开发机是北京时间，同一个 `generated_at` 曾因此含义不一致，足以让人误判数据新旧。新鲜度判断也一律用北京时间（`markFreshness()` / `bjNow()`），且只作辅助提示；**「数据日期」必须取 CSV 最后交易日 `__LATEST__`**，严禁用页面生成时间冒充数据日期，也别为消除节假日误报去接交易日历接口（会破坏静态页零外部依赖）。

> 另外两条工程经验：`docs/breadth.csv` 用 `utf-8-sig` 写 BOM，否则 Excel 打开中文表头乱码；本地通达信 `.day` 是 **32 字节小端**结构，早期解析踩过字节序坑（云端版不读 `.day`，但别把两套代码混着改）。

## 十、常见问题 FAQ

**Q1：页面只有半年数据？** 旧版 `OUT_DAYS=120`。现在默认 1300 个交易日（约 5 年），若仍只看到半年，说明浏览器加载了旧快照，强制刷新或在 Actions 里 Run workflow。

**Q2：指数曲线和宽度曲线对不上？** 现在是两张独立的图：主图只有 MA50 / MA200，指数在图 2 里用归一化分位 0-100（默认滚动 250 日，可切 5 年周期）与 MA200 占比分位同竖轴对比，背景红绿是 Spread。想看原始指数点位，点「显示原始走势」切到右轴基准 100。这些都是形状对比，不是收益率。

**Q3：滚轮没反应？** 需要 ECharts CDN 加载成功；离线打开时图表库缺失，页面会提示看数据表。CDN 挂了可把 echarts 下载到 `docs/` 并改 `<script src>`。

**Q4：Actions 红了但页面还有数据？** 正是设计：失败时脚本不覆盖已有 `docs/`，页面保留上次好结果。看日志是「仅成功取到 N 只」还是「有效样本不足」，别急着改阈值掩盖。

**Q5：首次跑很久？** 境外 runner 逐只约 5900 次请求，10~30 分钟正常。想快就 `--codes-file hs300.txt` 换成成分股池。

**Q6：为什么 5 年前的分母比现在小？** 幸存者偏差，见 2.4 与第十一章。

**Q7：可以只算某几个指数成分股吗？** 可以，准备一个每行 6 位代码的 txt，用 `--codes-file`，并在 workflow 命令里加同样参数。

**Q8：`a-stock-api` Worker 挂了会怎样？** 只影响幂等判断和校验卡片，日志出现 `[aux] 补充源不可用`，主计算照常。

**Q9：CSV 会不会越滚越大？** 不会，按日期合并去重后裁剪到 1300 行；`maintenance.yml` 另有 500 MB 兜底。

**Q10：为什么不用前复权？** 前复权会随未来分红改写历史值，5 年序列不稳定；后复权与它在本指标上等价但历史固定，见 2.2。

**Q11：新上市 / 退市 / 指数成分股调整会自动更新吗？** 新股与退市股**自动**纳入或剔除（每次运行重拉清单并写回 `codes.txt`）；ST 戴帽、沪深300 成分调整**不影响**本项目的股票池，因为口径是全市场 A 股正股而非指数成分股。新股满 51 根日线进 MA5/20/50 分母、满 200 根进 MA200 分母。详见 3.5。

**Q12：页面出现橙色「代码池兜底」条怎么办？** 说明主源 + 备用源本次都挂了，正在用 `codes.txt`。系统不会静默冻结：日期超过 7 天就会禁止幂等跳过、每次继续重试刷新。若连续多日橙色，去 Actions 日志看 `[pool] 主源失败` 的具体异常，或检查东财接口是否改版；绿色状态条 = 一切正常，无需人工介入。

**Q13：头部的「5 年百分位」和图 2 的「归一化分位」是一个东西吗？** 不是。头部是当前 MA200 占比在近 1300 个交易日中的 **percentile rank**（有多少比例的历史读数低于当前值）；图 2 的是**滚动 min-max 相对位置（250 日默认 / 1300 日可切换）**，用来和指数分位相减得到 Spread。两者数值可能差很远，都正常，详见 5.2。

**Q14：主图怎么只有两条线？MA5 / MA20 是不是没算了？** 仍在算：CSV、最近 15 日表、头部四张卡片都保留完整四档。只是应用户要求把短期噪声从主图移除，避免信号太乱。

## 十一、已知限制与免责声明

1. **幸存者偏差**：5 年历史用当前股票池回算，早期分母偏小，越往前偏差越大。
2. **ST 未剔除**，与标普 500 成分股口径不同；本项目是「全 A 股等权宽度」。
3. **前复权/后复权等价但非可成交价**，曲线只用于相对比较。
4. **GitHub cron 不保证准时**，高峰期可能延迟或跳过；双 cron 为兜底。
5. **境外访问东财可能被限流**，样本数会小幅波动；页面标注了每次的实际有效样本。
6. **未配置独立 PWA 图标 / 离线 Service Worker**，添加到主屏幕是浏览器默认图标；断网可看已生成的 HTML，但首次打开需联网。

结果为公开数据的统计计算，不构成投资建议；不上传任何行情软件客户端的本地数据文件。

### 12.2 两条链路的边界（最容易越界）

```text
主链路（算宽度，不可缺席）
  代码池三级：push2 spot_em ─失败→ code_name 备用源 ─失败→ codes.txt 兜底
              （任一成功都写回 codes.txt + 刷新日期标记）
  AKShare → push2his 逐股后复权日线 ──┐
          → 指数日线 ────────────────┼→ breadth.py → docs/

  a-stock-api Worker /api/market-breadth ─┘（只给 date + 校验卡片）
```

- 改**主计算**不要动 Worker 仓库；改 Worker 调用只动 `fetch_aux()` / 幂等判断那几行。
- Worker 属于另一个仓库 `wj624/a-stock-api`，它没有逐股历史与复权，**严禁把它接成主数据源**。

### 12.3 九个必踩坑（按踩坑频率排序）

1. **空数组 ≠ 没数据**：Worker 曾把上游失败吞成 `200 + {"data":[]}` 并缓存；本项目对应防线是 `MIN_VALID` / 取数下限 / 拒绝覆盖。任何新接口都要照这个模式写。
2. **分母**：停牌日不计入、每档均线独立分母、上市不足 `MIN_BARS`(51) 根日线者整只剔除、未满 200 根者不进 MA200 分母。改错不会报错，只会让曲线悄悄偏低。
3. **复权**：只有 `hfq` 序列是连续的；不要用不复权价，也不要混用两套复权口径。
4. **境外超时**：`socket.setdefaulttimeout(12)` 是全局的，删掉后 akshare 内部 `requests` 可能无限挂起，CI 会一直跑到 90 分钟超时。
5. **5 年回算**：`LOOKBACK_DAYS` 必须 ≥ 200 日均线预热 + 1300 输出日。减小它会让曲线左端出现假值。
6. **HTML 占位符**：模板用 `__XXX__` 唯一占位符一次性替换；改回 f-string 拼整页 JS 会因为大括号转义整页失效，且 `node --check` 能提前发现。
7. **股票池静默冻结**：最隐蔽的失败不是报错，而是长期用旧 `codes.txt` 还显示绿色。任何改动 `get_codes()` / 幂等判断的代码，都必须保留「每次重拉清单 + 日期标记 + 超 7 天禁止跳过 + 降级橙色告警」，否则新上市股票会永远进不来且无人察觉。
8. **归一化分位窗口**：`rolling_minmax_pct()` 只接受「当日及之前」的滚动窗口（250 默认 / 1300 可选），不能整段固定 min-max，也不能按图表显示窗口算，更不能把两套分位挪到前端实时算（会出现前视偏差或缩放漂移）。新增周期时两套都要在 Python 端算好写进 payload。图 2 切换 series 必须带 `replaceMerge:['series']`，否则 `setOption` 的 merge 会留下旧曲线，看起来像「切换没生效」或出现幽灵线。改完务必用 headless Chrome 加载 `docs/index.html`，确认 3 个 `<canvas>`、两种周期切换后 `CUR_SPREAD` 末值确实不同、且控制台无 JS 异常。
9. **图例状态别用事件缓存**：`legendselectchanged` 对 `dispatchAction` 不触发，靠它存偏好会让「切换视图后手动勾选丢失」；读 `getOption().legend[0].selected` 才可靠。图 2 两种视图的 series 名称不同（` 分位` / `（基准 100）`），重建图例时必须按指数 key 映射两套命名，否则默认关闭的上证 / 创业板分位会被重新打开。改完要分别验证「零操作切换」与「手动勾选后切换」两种场景。

**可调旋钮表见第八章**，改之前先确认是否同时需要改 `maintenance.yml` 的 `--max-rows`。

### 12.4 四类常见任务的 SOP

**A. 上游接口变了 / akshare 升级**
1. 本地跑 `--limit 300 --codes-file codes.txt --out test-out --force --min-valid 100`，确认 `df["日期"]` / `df["收盘"]` 字段名与单位没变。
2. 确认 `index_zh_a_hist` 三个代码仍返回日线。
3. 全量跑一次，比对 2026-09-21 锚点（MA200 ≈ 27.45%）与 2026-11-06 锚点（≈ 12.07%）。
4. 两处都对得上再升级 `requirements.txt`，并同步第九章第 7 条。

**B. 换股票池 / 加指数**
- 换池：只准备 `--codes-file` 文件，**不要改 `codes.txt`**（它是全市场兜底）。
- 加指数：只改 `INDEXES` 字典（代码、名称、颜色）+ 确认 `index_zh_a_hist` 支持该代码。前端会自动按 `DATA.indices` 生成曲线与图例。

**C. 曲线缺了一段 / 某天数据异常**
1. 先看 `docs/breadth.csv` 该日 `n_ma200` 是否明显低于前后（正常 5000+）。
2. 再看 Actions 日志里「历史日线 N/M，成功 K」的成功率，低于 80% 说明被限流。
3. 不要手填缺失日、不要用前一日顶替。第二天正常跑会自动重算整段 5 年历史。

**D. Action 红了怎么读**
1. 红在 `Compute market breadth`：看是 `仅成功取到 N 只`（限流）还是 `有效样本不足`（上游异常），都不是「当天没行情」。
2. 红在 `Commit report back to repo`：`git pull --rebase` 冲突，检查是不是有人手改了 `docs/`。
3. 计算成功但页面没变：`git diff --cached --quiet` 命中，说明辅助源日期与 CSV 最后日期相同（非交易日 / 已跑过），这是正常幂等。
