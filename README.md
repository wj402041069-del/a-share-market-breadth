## 一、这个系统在监测什么

| 曲线 | 含义 | 对标 |
|---|---|---|
| `pct_above_5` | 站上 5 日均线的股票占比 | `S5FD`，超短线情绪 |
| `pct_above_20` | 站上 20 日均线占比 | `S5TW`，1~4 周动能 |
| `pct_above_50` | 站上 50 日均线占比 | `S5FI`，中期趋势持续性 |
| `pct_above_200` | 站上 200 日均线占比 | `S5TH`，长期循环强度 |
| 沪深 300 / 上证综指 / 创业板指 | 可叠加对比的指数走势 | 与宽度共用时间轴 |
| 涨跌家数 / McClellan | 每日上涨、下跌家数与 EMA19−EMA39 | 广度动量 |

宽度是**等权**的，一只股票一票，不看市值。指数涨但宽度掉头，通常说明是少数权重在撑，属于典型脆弱结构——这正是这套指标的价值。

## 二、指标怎么算（S5TH 口径）

### 2.1 定义

`pct_above_N(t) = 当日「后复权收盘价 > 自身 N 日均线」的股票数 / 当日有效样本数`

### 2.2 复权：为什么必须用 `hfq`

`.day` / 东财不复权价格在除权日会出现人为跳空，直接算均线会得到假跌破。本地通达信版曾用 `gbbq` 自己算前复权；云端版直接取 `stock_zh_a_hist(adjust="hfq")` 后复权序列，价格天然连续。`close > MA_N(close)` 在整体等比例缩放下不变，所以前复权与后复权等价，且后复权历史值不会因未来分红被改写，更适合做 5 年时间序列。

**实测锚点**：2026-09-21，不复权 MA200 占比 24.61%，复权后 27.57%，差约 3 个百分点。

### 2.3 分母与样本（最容易算错的地方）

- 股票池：沪深京 A 股正股（600/601/603/605/688/689、000/001/002/003/300/301、43/83/87/92 开头），排除指数、基金、债券、B 股；ST 未单独剔除
- 剔除上市不足 200 个交易日的股票；**停牌日不计入当日分母**
- **每档均线独立分母**：MA200 还没算出来的股票不能算成「未站上」，否则 5 年曲线左端会被系统性压低
- MA 按个股自己的交易日序列滚动（跳过停牌），与行情软件口径一致

### 2.4 5 年历史是「回算」，不是「存档」

`LOOKBACK_DAYS=2400` 天（约 6.5 年），每次运行都把全市场历史拉回来重算最近 **1300 个交易日**（约 5 年）。所以 **CSV 不需要一天天累积**，也不会随时间漂移。

代价是**幸存者偏差**：5 年前的宽度是用「今天还在池子里的股票」回算的，当时未上市 / 现已退市的股票不在其中，越往前分母越小。看板底部与第十一章都写明了这一点，严禁把早期数值表述成「当时的真实全市场宽度」。

### 2.5 三大指数怎么放到同一张图

指数传的是**原始收盘价**，归一化在浏览器里按**当前缩放窗口动态重算**：

- **独立竖轴（默认）**：以窗口首日 = 100，指数画在右轴，看相对涨跌
- **同竖轴对比**：窗口内 min-max 线性映射到 0-100，切到左轴，与 4 条宽度曲线共用同一根竖轴，直接看形状是否同步

因为按窗口重算，拖动滑块或点「半年」时曲线不会错位。指数用 `connectNulls` 补齐停牌 / 未上市的空洞。

## 三、数据源、单位与剔除项

### 3.0 数据源总表（先看这张）

| 用途 | 接口 | 上游域名 | 能否缺席 |
|---|---|---|---|
| 全市场代码清单 | `ak.stock_zh_a_spot_em()` | `push2.eastmoney.com` | ✅ 可，回退 `codes.txt` |
| 逐股后复权日线 | `ak.stock_zh_a_hist(adjust="hfq")` | `push2his.eastmoney.com` | ❌ 主计算依赖 |
| 三大指数日线 | `ak.index_zh_a_hist()` | 东财 | ✅ 可，对应曲线留空 |
| 当日快照校验 / 幂等 | `a-stock-api /api/market-breadth` | Cloudflare Worker | ✅ 可，静默跳过 |

### 3.1 `wj624/a-stock-api` 评估结论：**不是更好，不能当主源**

| 本项目需要 | 该数据源 | 判定 |
|---|---|---|
| 全市场逐股历史日线 | README 明确 `/api/spot` 未提供（push2 分页 60 页 > 免费 Worker 50 子请求） | ❌ |
| 复权收盘价 | `/api/kline` 无 `adjust`；`/api/futures-kline` 明确未复权 | ❌ |
| 站上 N 日均线的历史序列 | `/api/market-breadth` 仅当日快照，`history_supported` 恒 false、忽略 `date` | ❌ |
| 当日涨跌 / 涨停 / 连板 | 一次请求，云出口实测可达 | ✅ |
| 交易日历、指数日 K | `/api/trade-calendar`、`/api/kline` 可用 | ✅ |

本项目只把它用在两处：**① 用 `date` 做幂等判断**（兜底 cron 命中当天就不重复拉 5900 只）；**② 结果页「当日快照校验」卡片**。它失败时主流程照常跑完。

### 3.2 它暴露的真问题：push2 的 WAF

该 README 明确写「东财 `push2.eastmoney.com` 对 Cloudflare / 云出口 IP 有 WAF 拦截（502）」，而 `stock_zh_a_spot_em` 正是 push2。于是全市场代码清单被做成随仓库提交的 **`codes.txt`（5923 只）**：在线快照成功就刷新它，失败就回退它；逐股历史走 `push2his`，不受这条限制。

### 3.3 单位、颜色与口径

- 价格单位：元（后复权），仅用于相对比较，**不是可成交价**
- 宽度单位：百分比 0-100；McClellan：家数差（无量纲）
- **红涨绿跌**：上涨 `#d64545`、下跌 `#1f9d6b`（A 股习惯，严禁反色）
- 指数归一化基准 100（独立竖轴）/ 0-100（同竖轴），是形状对比，不代表收益率

### 3.4 明确剔除项

指数、基金、债券、B 股、北交所指数、上市不足 200 交易日者、停牌日、数据停更 / 退市股。**ST 未剔除**（与 TradingView 成分股口径不同，是有意选择）。

## 六、GitHub Actions 部署与定时

- 仓库：`wj402041069-del/a-share-market-breadth`（public，Pages 源为 `main` / `docs`）
- `breadth.yml`：`cron: '30 8 * * 1-5'`（北京 16:30）+ `'0 10 * * 1-5'`（北京 18:00 兜底），`timeout-minutes: 60`
- GitHub 的 cron 一律按 **UTC** 解释，且不保证准时；双 cron 就是为此准备的。第二次若发现辅助源日期 == CSV 最后日期，脚本**幂等跳过**，几乎零成本
- `maintenance.yml`：每周一北京 11:00 读仓库 `size`，**< 512000 KB 一个字节都不改**；达到阈值才裁剪 CSV 到 365 天 / 删旧快照，正常 commit，**绝不 force push、不重写 main 历史**
- CI 提交用 `GITHUB_TOKEN`（workflow 已声明 `permissions: contents: write`），**不需要任何 PAT / Secrets**

## 九、防 Bug 铁律（改动代码前必读）

> **以下 12 条均来自真实踩坑，严禁回退。**

1. **必须用后复权 `adjust="hfq"`**。严禁用不复权收盘价直接算 MA：除权日会假跌破，实测 MA200 占比差约 3 个百分点（24.61% vs 27.57%）。
2. **`codes.txt` 兜底不能删，且只有「在线快照 ≥3000 只」才允许写回**。push2 对云出口有 WAF 502；把异常小的快照写进兜底文件，等于把一次限流放大成长期数据空洞。
3. **「200 + 空数组」不等于「今天没数据」**。有效样本 < `MIN_VALID` 或取数成功 < 200 只时，必须非 0 退出且**不覆盖** `docs/`；严禁用前一日数据顶替缺失日。
4. **停牌日不计入当日分母，每档均线独立分母**。把 MA200 无值的股票算成「未站上」，会让 5 年曲线左端系统性偏低且不会报错。
5. **交易日历用全市场个股日期并集（阈值 30%）**，严禁只依赖指数文件。本地版用上证指数日历时曾误剔 920 只股票。
6. **红涨绿跌**：上涨 `#d64545`、下跌 `#1f9d6b`。严禁反色。
7. **依赖锁死 `akshare==1.20.21 / pandas<3 / numpy<3`**。pandas 3.x 移除 `resample('M')` 等 API，会打断 akshare 内部逻辑；升级前必须本地全量验证。
8. **境外 runner 四件套不能删**：`socket.setdefaulttimeout(12)`、并发 10、重试 2、`timeout-minutes: 60`。akshare 内部 `requests` 未设超时，境外遇连接问题会挂死；首次全量实测 30 分钟未结束。
9. **5 年历史是「当前股票池回算」**，有幸存者偏差。严禁在页面 / 文档里表述为「当时的真实全市场宽度」。
10. **HTML 用唯一占位符 `__XXX__` 整段替换，不用 f-string 拼整页 JS**。一处括号转义错整页图表全废；生成后必须抽出 `<script>` 跑 `node --check`。
11. **仓库内绝不写任何 PAT / Token**，CI 用 `GITHUB_TOKEN`；提交前 `grep -R "ghp_"` 扫一遍。
12. **绝不 force push、不重写 main 历史**。500 MB 清理只裁剪 `docs/` 数据文件，正常 commit。

> 另外两条工程经验：`docs/breadth.csv` 用 `utf-8-sig` 写 BOM，否则 Excel 打开中文表头乱码；本地通达信 `.day` 是 **32 字节小端**结构，早期解析踩过字节序坑（云端版不读 `.day`，但别把两套代码混着改）。

## 十、常见问题 FAQ

**Q1：页面只有半年数据？** 旧版 `OUT_DAYS=120`。现在默认 1300 个交易日（约 5 年），若仍只看到半年，说明浏览器加载了旧快照，强制刷新或在 Actions 里 Run workflow。

**Q2：指数曲线和宽度曲线对不上？** 默认「独立竖轴」把指数画在右轴（基准 100）。点「同竖轴对比」会按当前窗口 min-max 归一到 0-100 并移到左轴——那是形状对比，不是收益率。

**Q3：滚轮没反应？** 需要 ECharts CDN 加载成功；离线打开时图表库缺失，页面会提示看数据表。CDN 挂了可把 echarts 下载到 `docs/` 并改 `<script src>`。

**Q4：Actions 红了但页面还有数据？** 正是设计：失败时脚本不覆盖已有 `docs/`，页面保留上次好结果。看日志是「仅成功取到 N 只」还是「有效样本不足」，别急着改阈值掩盖。

**Q5：首次跑很久？** 境外 runner 逐只约 5900 次请求，10~30 分钟正常。想快就 `--codes-file hs300.txt` 换成成分股池。

**Q6：为什么 5 年前的分母比现在小？** 幸存者偏差，见 2.4 与第十一章。

**Q7：可以只算某几个指数成分股吗？** 可以，准备一个每行 6 位代码的 txt，用 `--codes-file`，并在 workflow 命令里加同样参数。

**Q8：`a-stock-api` Worker 挂了会怎样？** 只影响幂等判断和校验卡片，日志出现 `[aux] 补充源不可用`，主计算照常。

**Q9：CSV 会不会越滚越大？** 不会，按日期合并去重后裁剪到 1300 行；`maintenance.yml` 另有 500 MB 兜底。

**Q10：为什么不用前复权？** 前复权会随未来分红改写历史值，5 年序列不稳定；后复权与它在本指标上等价但历史固定，见 2.2。

## 十一、已知限制与免责声明

1. **幸存者偏差**：5 年历史用当前股票池回算，早期分母偏小，越往前偏差越大。
2. **ST 未剔除**，与标普 500 成分股口径不同；本项目是「全 A 股等权宽度」。
3. **前复权/后复权等价但非可成交价**，曲线只用于相对比较。
4. **GitHub cron 不保证准时**，高峰期可能延迟或跳过；双 cron 为兜底。
5. **境外访问东财可能被限流**，样本数会小幅波动；页面标注了每次的实际有效样本。
6. **未配置独立 PWA 图标 / 离线 Service Worker**，添加到主屏幕是浏览器默认图标；断网可看已生成的 HTML，但首次打开需联网。

结果为公开数据的统计计算，不构成投资建议；不上传任何行情软件客户端的本地数据文件。

## 十二、给 AI 的维护提示词

> **这一章是写给「下一次接手这个仓库的 AI」的操作手册。人类读者可以跳过；但如果任务涉及改代码、修数据、换标的、加曲线，请先读完 12.1~12.4 再动手，12.5 是可整段复制的提示词。**

### 12.1 仓库速览：哪个文件能改、改了会炸什么

| 文件 | 职责 | 改了会炸什么 |
|---|---|---|
| `breadth.py` | **单一主程序**：取数、复权、日历、矩阵计算、CSV/HTML 生成、运行时护栏、全部常量 | 改常量会直接改变口径；改 `compute` 的分母逻辑会静默污染 5 年曲线 |
| `housekeeping.py` | 纯标准库体积裁剪，供 `maintenance.yml` 调用 | 不依赖 akshare，别顺手 import 进来 |

### 12.2 两条链路的边界（最容易越界）

```text
主链路（算宽度，不可缺席）
  AKShare → push2 代码清单（失败 → codes.txt）
          → push2his 逐股后复权日线 ──┐
          → 指数日线 ────────────────┼→ breadth.py → docs/
                                      │
辅助链路（可选，失败静默跳过）          │
  a-stock-api Worker /api/market-breadth ─┘（只给 date + 校验卡片）
```

- 改**主计算**不要动 Worker 仓库；改 Worker 调用只动 `fetch_aux()` / 幂等判断那几行。
- Worker 属于另一个仓库 `wj624/a-stock-api`，它没有逐股历史与复权，**严禁把它接成主数据源**。
- 只要 `/api/market-breadth` 的 `date` 字段不变，本项目一行都不用改。

### 12.3 六个必踩坑（按踩坑频率排序）

1. **空数组 ≠ 没数据**：Worker 曾把上游失败吞成 `200 + {"data":[]}` 并缓存；本项目对应防线是 `MIN_VALID` / 取数下限 / 拒绝覆盖。任何新接口都要照这个模式写。
2. **分母**：停牌日不计入、每档均线独立分母、上市不足 200 日剔除。改错不会报错，只会让曲线悄悄偏低。
3. **复权**：只有 `hfq` 序列是连续的；不要用不复权价，也不要混用两套复权口径。
4. **境外超时**：`socket.setdefaulttimeout(12)` 是全局的，删掉后 akshare 内部 `requests` 可能无限挂起，CI 会一直跑到 60 分钟超时。
5. **5 年回算**：`LOOKBACK_DAYS` 必须 ≥ 200 日均线预热 + 1300 输出日。减小它会让曲线左端出现假值。
6. **HTML 占位符**：模板用 `__XXX__` 唯一占位符一次性替换；改回 f-string 拼整页 JS 会因为大括号转义整页失效，且 `node --check` 能提前发现。

**可调旋钮表见第八章**，改之前先确认是否同时需要改 `maintenance.yml` 的 `--max-rows`。

### 12.4 四类常见任务的 SOP

**A. 上游接口变了 / akshare 升级**
1. 本地跑 `--limit 300 --codes-file codes.txt --out test-out --force --min-valid 100`，确认 `df["日期"]` / `df["收盘"]` 字段名与单位没变。
2. 确认 `index_zh_a_hist` 三个代码仍返回日线。
3. 全量跑一次，比对 2026-09-21 锚点（MA200 ≈ 27.45%）与 2026-11-06 锚点（≈ 12.07%）。
4. 两处都对得上再升级 `requirements.txt`，并同步第九章第 7 条。

**B. 换股票池 / 加指数**
- 换池：只准备 `--codes-file` 文件，**不要改 `codes.txt`**（它是全市场兜底）。
- 加指数：只改 `INDEXES` 字典（代码、名称、颜色）+ 确认 `index_zh_a_hist` 支持该代码。前端会自动按 `DATA.indices` 生成曲线与图例。

**C. 曲线缺了一段 / 某天数据异常**
1. 先看 `docs/breadth.csv` 该日 `n_ma200` 是否明显低于前后（正常 5000+）。
2. 再看 Actions 日志里「历史日线 N/M，成功 K」的成功率，低于 80% 说明被限流。
3. 不要手填缺失日、不要用前一日顶替。第二天正常跑会自动重算整段 5 年历史。

**D. Action 红了怎么读**
1. 红在 `Compute market breadth`：看是 `仅成功取到 N 只`（限流）还是 `有效样本不足`（上游异常），都不是「当天没行情」。
2. 红在 `Commit report back to repo`：`git pull --rebase` 冲突，检查是不是有人手改了 `docs/`。
3. 计算成功但页面没变：`git diff --cached --quiet` 命中，说明辅助源日期与 CSV 最后日期相同（非交易日 / 已跑过），这是正常幂等。
